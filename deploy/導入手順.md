# キャッシュフロー診断 ― 導入手順

データ蓄積機能とアクセス制限を追加した版の設置手順です。
上から順に進めれば完了します。所要時間はおよそ 1〜1.5 時間です。

---

## 全体の構成

```
お客様のブラウザ（WordPressサーバー上の /cf/index.html）
        │  ① 入力値を送信
        ▼
Google Apps Script（判定ロジックの本体）
        │  ② 判定して結果を返す   ③ 同時に1行記録
        ▼                          ▼
   ブラウザに結果表示        Googleスプレッドシート
```

**判定の閾値・診断タイプの文言は GAS 側にのみ存在します。**
ブラウザの「ページのソースを表示」で見えるのは入力フォームと結果の表示部分だけです。

---

## STEP 1 ― スプレッドシートを作る

1. Google ドライブで新しいスプレッドシートを作成（名前は「キャッシュフロー診断_回答」など）
2. URL から ID をコピーする

```
https://docs.google.com/spreadsheets/d/★この部分がID★/edit
```

見出し行は最初の書き込み時に自動で作られるので、手で用意する必要はありません。

---

## STEP 2 ― GAS を設置する

1. 作成したスプレッドシートで **拡張機能 → Apps Script** を開く
2. 既定の `myFunction` を全部消し、`gas/Code.gs` の中身をすべて貼り付ける
3. ファイル冒頭の `CONFIG` を書き換える

```javascript
const CONFIG = {
  SHEET_ID:   '1AbC...（STEP1でコピーしたID）',
  SHEET_NAME: 'responses',
  TOKEN:      'Fc2026-xxxxx'   // 好きな文字列。推測されにくいものに
};
```

4. 保存（Ctrl+S）
5. 関数の選択で **`testAppend`** を選び、**実行**
   - 初回は権限の確認が出ます。「詳細」→「（プロジェクト名）に移動」→「許可」
   - スプレッドシートにテスト行が1行追加されれば成功です（確認後、その行は消してOK）
6. **デプロイ → 新しいデプロイ → 歯車アイコン → ウェブアプリ**

| 項目 | 設定値 |
|---|---|
| 次のユーザーとして実行 | **自分** |
| アクセスできるユーザー | **全員** |

> 「全員」でないと外部のページから呼び出せません。合言葉（TOKEN）で保護しているので問題ありません。

7. 発行された **ウェブアプリURL** をコピー
   （`https://script.google.com/macros/s/AKfy.../exec` の形）
8. そのURLをブラウザで開いて `{"ok":true,"msg":"endpoint alive"}` が表示されれば疎通OK

---

## STEP 3 ― index.html に設定を書き込む

リポジトリ直下の `index.html`（GitHub Pagesが配信している実体）を開き、`<script>` の冒頭にある `CONFIG` を書き換えます。

```javascript
const CONFIG = {
    endpoint:       'https://script.google.com/macros/s/AKfy.../exec',  // STEP2のURL
    token:          'Fc2026-xxxxx',        // STEP2のTOKENと完全に同じ文字列
    appVersion:     'v1.6.3',
    consentVersion: '2026-09-21'
};
```

あわせて、**同意文面の問い合わせ先**を埋めてください。
ファイル内を「会社名をここに」で検索すると該当箇所が見つかります（赤字で表示されています）。

```html
<span style="color:#b91c1c;font-weight:700;">【会社名をここに】 【問い合わせ先メール／電話をここに】</span>
```

## STEP 4 ― サーバーに置いてアクセス制限をかける

WordPress が動いているサーバーの `public_html` の下に、**WordPress とは別のディレクトリ**を作ります。

```
public_html/
├── wp-content/ …（WordPress本体。触らない）
├── index.php
└── cf/                ← 新規作成
    ├── index.html     ← STEP3で編集したファイル
    ├── .htaccess      ← deploy/htaccess-sample.txt をリネームして設置
    └── .htpasswd      ← ユーザー名とパスワード
```

> **固定ページに貼り付ける方法は避けてください。**
> このHTMLは独自のCSSを全部内蔵しているため、WordPress のテーマCSSと衝突してレイアウトが崩れます。
> 別ディレクトリに実ファイルとして置くのが最も安全です。

### Basic認証の設定

一番簡単なのは、**サーバーのコントロールパネルの「アクセス制限」機能**を使う方法です。
（エックスサーバー：「アクセス制限」／さくら：「ディレクトリのパスワード制限」）
ディレクトリ `/cf/` を選んでユーザー名とパスワードを登録するだけで完了します。

手で設定する場合は `deploy/htaccess-sample.txt` を参照してください。

### 動作確認

`https://（自社ドメイン）/cf/` にアクセスして、

1. ユーザー名・パスワードを聞かれる
2. 同意画面が表示される
3. 最後まで入力して診断結果が出る
4. スプレッドシートに1行増えている

ここまで確認できれば完了です。

## STEP 5 ― 社員への配り方

WordPress の固定ページ（会社概要の下など、社員が見つけられる場所）に、
`https://（自社ドメイン）/cf/` へのリンクを1本置いてください。

### 担当者別・流入元別に記録したい場合

URLにパラメータを付けて配ると、その値がそのまま記録されます。

| URL | 記録される内容 |
|---|---|
| `/cf/?staff=tanaka` | `staff` 列に `tanaka` |
| `/cf/?src=seminar-0401` | `source` 列に `seminar-0401` |
| `/cf/?staff=tanaka&src=seminar-0401` | 両方 |

社員ごとにブックマークしてもらえば、誰が何件実施したかが自動で集計できます。
セミナーや別サイトから誘導する場合は `src` を配布先ごとに変えてください。

## 集計のしかた

スプレッドシートに新しいシートを作り、A1 に数式を入れます。
データは `responses` シートの **A列〜CU列（全99列）** に入ります。

主な列の対応は次のとおりです。

| 列 | 内容 | 列 | 内容 |
|---|---|---|---|
| A | 日時 | AC | 純金融資産 |
| C | 担当者 | AD | 家賃・住宅ローン |
| D | 流入元 | BE | 月間資産形成可能額 |
| H | 年齢 | BG | ① 貯蓄率 |
| I | 性別 | BH | ② 同年代での位置（上位％） |
| J | 都道府県 | BI | ③ 投資稼働率 |
| K | 世帯構成 | BJ | ④ 自由度スコア |
| N | 住居形態 | BO | 総合スコア |
| O | 就業形態 | BP | 診断タイプ |
| P | 世帯の働き方 | BR | 想定年金額（年額） |
| | | BS | 年金の前提 |
| | | BU | 配偶者の就業形態 |
| | | BV | ②の比較対象グループ |
| | | BW | 同グループの中央値 |
| | | BY | ①の推計累計収入 |
| | | CE | ③の運用資産 |
| | | CG | ④の老後想定支出 |
| | | CI | 借入の有無 |
| | | CJ | 奨学金残高 |
| | | CK | 自動車ローン残高 |
| | | CL | カードローン・リボ残高 |
| | | CM | その他ローン残高 |
| | | CN | 住宅ローン残高 |
| | | CS | 手取り年収に対する返済割合 |
| | | CT | 借入・返済コンディション |

**① 年代 × 性別の平均スコア**

```
=QUERY(responses!A:CU,
  "select round(H/10)*10, I, count(A), avg(BO), avg(BG), avg(BH)
   where A is not null and H > 0
   group by round(H/10)*10, I
   label round(H/10)*10 '年代', I '性別', count(A) '件数',
         avg(BO) '総合スコア', avg(BG) '貯蓄率', avg(BH) '上位％（小さいほど上位）'", 1)
```

**② 住居形態別の家賃・貯蓄額の平均**

```
=QUERY(responses!A:CU,
  "select N, count(A), avg(AD), avg(BE), avg(AC)
   where A is not null
   group by N
   order by count(A) desc
   label N '住居形態', count(A) '件数', avg(AD) '平均家賃',
         avg(BE) '月間資産形成額', avg(AC) '平均純資産'", 1)
```

**③ 担当者別の実施件数**

```
=QUERY(responses!A:CU,
  "select C, count(A) where A is not null group by C order by count(A) desc
   label C '担当者', count(A) '実施件数'", 1)
```

`group by` の列を変えるだけで、世帯構成別・就業形態別・都道府県別なども同じ形で出せます。
慣れてきたら「データ → ピボットテーブル」のほうが手早いです。

> 列記号は `Code.gs` の `COLS` の並び順に対応しています。
> **COLS に項目を追加するときは必ず末尾に足してください。**
> 途中に挿入すると、それ以降の列記号がすべてズレて既存の数式が壊れます。

## 運用上の注意

### 判定基準を変更するとき

1. GAS の `judge()` を編集
2. **必ず「デプロイを管理」→ 鉛筆アイコン → バージョン「新バージョン」→ デプロイ**
   （保存しただけでは反映されません。URLは変わりません）
3. `index.html` の `CONFIG.appVersion` を上げる（例 `v1.0.0` → `v1.1.0`）

appVersion を上げておかないと、閾値を変えた前後のデータが混ざって集計できなくなります。

### ①の「残す力」はどう決まるか

```
残せた割合 = 金融資産合計 ÷ 推計した累計手取り収入
```

分母の累計収入は、**現在の収入を起点に、性別・年齢別の賃金カーブで
過去の各年の収入水準を割り戻して合算**しています。

出典：厚生労働省「令和7年賃金構造基本統計調査」第2表（性、年齢階級別賃金）

**なぜこうしたか**

旧来は「現在の年収 × 勤続年数」で代用していました。日本の賃金カーブは
右肩上がりなので、この方法だと過去の収入を実際より多く見積もることになり、
**年齢が上がるほど「残す力」が不当に低く出ていました**。

推計値の変化（累計収入）:

| プロフィール | 旧：年収×勤続 | 新：カーブ推計 | 差 |
|---|---|---|---|
| 30歳・男性・勤続8年・手取450万 | 3,600万円 | 2,965万円 | −18% |
| 40歳・男性・勤続18年・手取510万 | 9,180万円 | 7,249万円 | −21% |
| 50歳・男性・勤続28年・手取700万 | 19,600万円 | 15,607万円 | −20% |
| 40歳・女性・勤続18年・手取420万 | 7,560万円 | 6,835万円 | −10% |
| 50歳・女性・勤続28年・手取450万 | 12,600万円 | 11,769万円 | −7% |

女性の補正が小さいのは、女性の賃金カーブが男性より平坦なためです
（20～24歳=100として、男性は55～59歳で181.4、女性は127.6がピーク）。

**この推計の限界**

- 本人の収入が同性・同年齢の平均的なカーブに沿ってきたとみなしています。
  転職・休職・独立などの個別事情は反映されません
- 賃金カーブは額面ベース、入力は手取りベースです。累進課税により手取りの伸びは
  額面より緩やかなので、過去の収入をやや低めに見積もる方向に働きます
- 賃金カーブに賞与は含まれません。賞与は年齢とともにより急に伸びるため、
  上記とは逆方向に働きます（両者は一部相殺します）
- 勤続年数が「年齢−15」を超える入力は、15歳就業として丸めます

**評価の閾値について**

分母が小さくなった分、割合は全体的に高めに出ます。検証した6ケースのうち
評価が変わったのは1件（58歳・要改善→標準）だけでしたが、**閾値（勤続年数別の
15%/8%/3% 等）は社内基準のままです**。運用しながら見直してください。

### 入力チェック（v1.6.2）

金額・借入残高・返済額にマイナス値を入れると、画面で修正を求めます。
GAS側でもマイナス値の送信を拒否し、誤入力が集計に混ざるのを防ぎます。
単身・ひとり親世帯では「世帯の働き方」を「単身（自分のみ）」にし、年金試算へ配偶者分を加えません。
純金融資産や月間資産形成可能額のマイナス値は、計算結果として引き続き表示します。
### 借入・返済はどう評価するか

v1.6.0 から、金融資産の評価と借入の評価を分離しています。
奨学金や自動車ローンがあるだけで、①〜④の評価や総合点が下がることはありません。

- ①〜④：負債を差し引く前の金融資産で評価
- 借入：種類・残高・毎月返済額・手取り年収に対する返済割合を別表示
- 奨学金のみで返済割合が10％以下：「奨学金を計画的に返済中」
- 自動車・その他ローンで返済割合が10％以下：「無理のない範囲で返済中」
- 返済割合10％超：「返済と貯蓄のバランスに注意」
- 返済割合20％超：「返済負担が大きめ」
- カードローン・リボ残高あり：「高金利の借入を優先確認」
- 住宅ローン：住宅資産の価値を入力していないため金融資産から差し引かず、参考情報と住居費として表示

「返済考慮後の現在地」も参考表示しますが、総合点には使用しません。
これにより、若い方の教育目的の借入と、高金利・高負担の借入を同じ扱いにしない設計です。
### ②の「同年代での位置」はどう決まるか

公的調査の**金融資産保有額の分布**と比較し、同年代・同世帯類型の中で上位何％に
あたるかを算出しています。

出典：金融経済教育推進機構（J-FLEC）「家計の金融行動に関する世論調査（2025年）」
各種分類別データ（令和7年）／設問2(a)「金融資産保有額（金融資産を保有していない世帯を含む）」

| 比較グループ | 中央値の例 |
|---|---|
| 二人以上世帯・30歳代（n=648） | 311万円 |
| 二人以上世帯・40歳代（n=1,052） | 500万円 |
| 二人以上世帯・50歳代（n=1,024） | 700万円 |
| 単身世帯・30歳代（n=325） | 100万円 |
| 単身世帯・40歳代（n=324） | 100万円 |
| 単身世帯・50歳代（n=366） | 120万円 |

**設計上のポイント**

- **偏差値ではなくパーセンタイル**を使っています。金融資産は分布が右に大きく裾を
  引いており（平均値が中央値の約3倍）、偏差値にすると中央値の世帯が50を大きく
  下回るなど直感に反する値になるためです
- **純資産ではなく金融資産（負債を差し引く前）**で比較しています。調査の
  「金融資産保有額」の定義に合わせるためです
- 階級の中は線形補間していますが、**公表されている中央値がちょうど上位50％になる
  よう補正**しています。検算では12グループ中すべてが誤差2.8pt以内に収まっています
- 3000万円以上は階級に上限がなく内挿できないため「上位◯％以内」と表示されます

### ③の「働かせる力」はどう決まるか

```
投資稼働率 = 運用に回っている資産 ÷（金融資産合計 − 生活防衛資金）
```

**運用に回っている資産 = 投資信託・株式・債券 ＋ iDeCo・企業型DC・持株会**

v1.5.0 で資産の入力欄を6つに分けました。以前は「その他（投資信託等）」の1項目
だけだったため、**iDeCo・企業型DC・持株会をお持ちの方は実態より低く出ていました**。

| 入力欄 | 金融資産合計 | 運用資産 |
|---|---|---|
| 普通預金 | ● | |
| 定期預金 | ● | |
| 投資信託・株式・債券（NISA・外貨建て含む） | ● | ● |
| iDeCo・企業型DC・持株会 | ● | ● |
| 貯蓄型保険（解約返戻金） | ● | |
| その他の金融資産 | ● | |

**貯蓄型保険を運用資産に含めていないのは意図的です。** 利回りが低く途中で
引き出しにくいため、「動いていない資産」として扱います。保険に資金が偏っている
方は稼働率が低く出ますが、これは診断として正しいシグナルです。

**不動産・車は入力しません。** ②の比較に使う公的調査の「金融資産保有額」が
実物資産を含まない定義のため、揃えています。

### ④の想定年金額はどう決まるか

本人と配偶者それぞれについて「就業形態 × 性別」から月額を引き、合算しています。

| 区分 | 月額 | 備考 |
|---|---|---|
| 厚生年金・男性 | 173,033円 | 男子65歳以上の実績平均 |
| 厚生年金・女性 | 114,797円 | 女子65歳以上の実績平均 |
| 厚生年金・性別不明 | 150,289円 | 男女計の平均 |
| 国民年金のみ（自営業・パート等） | 54,353円 | 男女別の公表値なし |
| 第3号被保険者（専業主婦・主夫） | 59,310円 | 男女別の公表値なし |

配偶者の就業形態は、世帯の働き方で「共働き」「片働き」を選んだときだけ入力欄が出ます。
未入力の場合は、片働きなら第3号相当、共働きなら本人と同じ就業形態として推定し、
結果画面の前提欄に「（推定）」と表示されます。

### ④の「老後の支出」はどう決まるか

v1.5.0 まで「老後の支出 ＝ 現在の支出」としていましたが、実際には無くなる費目が
あり、逆に医療費は増えます。入力内容をもとに補正しています。

**差し引くもの**（65歳までに終わるとみなす）
- 教育費・習い事
- 奨学金返済
- その他ローン返済
- 住宅ローン ※「持ち家（住宅ローン返済中）」の場合のみ。賃貸・社宅・実家は住居費が続くとみなす

**加えるもの**
- 医療費 … 家計調査の高齢者世帯の実績（夫婦17,941円／単身8,388円）まで引き上げ

出典：総務省統計局「家計調査年報（家計収支編）2025年」表2

### ④の必要資産に下限を置いている理由

不足額の25年分（4%ルール）だけで計算すると、**年金が支出をほぼ賄える世帯では
必要額がゼロ近くまで小さくなり、資産がわずかでも「目標達成」と出てしまいます**。

実際、検証では40歳・純資産400万円の世帯が達成率260%と判定されました。

そこで家計調査の次の事実を下限の根拠にしています。

| 世帯 | 実収入 | 消費支出＋非消費支出 | 毎月の差額 |
|---|---|---|---|
| 65歳以上の夫婦のみの無職世帯 | 254,395円 | 296,829円 | **−42,434円** |
| 65歳以上の単身無職世帯 | 131,456円 | 161,435円 | **−29,980円** |

**高齢無職世帯は平均して毎月赤字で、資産を取り崩して生活しています。**
